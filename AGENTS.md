Canonical instructions for every coding agent working on this repo (Claude Code, Codex, Cursor, Copilot, Gemini, …).
`CLAUDE.md` only imports this file — edit here, not there.

## Project
writePad is an iPad-only app for handwritten notes and PDF reading/annotation (GoodNotes / FreeNotes style).
Roadmap and milestone checklist: `PLAN.md`. Tick boxes there when a milestone item is done.

## Stack
- Swift 6 (strict concurrency), SwiftUI, UIKit only where needed
- PencilKit for ink, PDFKit for PDFs, SwiftData for the library index (titles, folders, dates)
- iPadOS 18+ deployment target, `TARGETED_DEVICE_FAMILY = 2` (iPad only)
- Xcode 27+, project generated by XcodeGen

## Commands
```bash
xcodegen generate                      # after adding/removing/moving files or editing project.yml
swiftlint lint --quiet                 # also runs as a build phase
swiftformat writePad writePadTests     # optional formatting

# build + all tests (unit + UI). iPhone simulators are rejected — use an iPad.
xcodebuild test -project writePad.xcodeproj -scheme writePad \
  -destination 'platform=iOS Simulator,name=iPad Pro 11-inch (M5)' -derivedDataPath build \
  -parallel-testing-enabled NO -collect-test-diagnostics never

# unit tests only (fast)
xcodebuild test -project writePad.xcodeproj -scheme writePad \
  -destination 'platform=iOS Simulator,name=iPad Pro 11-inch (M5)' -derivedDataPath build \
  -collect-test-diagnostics never -only-testing:writePadTests
```
Scale tests (`LargePDFTests`, `LargePDFUITests`) use a generated 120-page PDF; to run them on a real document add
`TEST_RUNNER_WRITEPAD_LARGE_PDF=/absolute/path/book.pdf` before `xcodebuild` (don't commit large PDFs).
UI tests take several minutes. Without `-collect-test-diagnostics never`, a hung run spends up to 10 minutes in `simctl diagnose`.
If `name=` matching fails, use `xcrun simctl list devices available | grep iPad` and pass `id=<UUID>`.

## Layout
```

writePad/App/               app entry, scene lifecycle (flushes autosave on background), StorageLocation
writePad/Models/            Codable models: NotebookManifest, PageInfo, PageBackground
writePad/Storage/           NotebookStore — reads/writes .writepad packages
writePad/Features/Editor/   NotebookCanvasView (one zoomable PKCanvasView, pages stacked), PageLayout
                            (page geometry + merge/split of per-page drawings), PageBackgroundRenderer,
                            EditorViewModel (+ saving extension), SaveTiming, PageThumbnailJob,
                            NotebookEditorView, PageSidebarView, ShapeRecognizer (pure geometry) and
                            ShapeSnapper (hold-to-snap hook on any PKCanvasView)
writePad/Features/Library/  LibraryView/ViewModel (SwiftData index, folders, search, sort), NotebookCard
writePad/Features/PDF/      PDFNotebook (document, markups, outline, search), PDFCanvasView (PDFView +
                            per-page PKCanvasView overlays), PDFSidebarView, PDFTools
writePad/Features/Export/   NotebookExporter (flattened PDF / PNG), ExportMenu (share sheet)
writePadTests/              Swift Testing (`import Testing`, `@Test`, `#expect`)
writePadUITests/            XCUITest; always launch via `XCUIApplication.isolated()`
TestSupport/                shared by both test targets (e.g. PDFFixture builds small PDFs in code)
```

## Rules
- **Never edit `writePad.xcodeproj` by hand.** Change `project.yml`, then run `xcodegen generate`. The generated project is committed so it opens with a double-click.
- **Never lose ink.** All writes use `.atomic`; one save is `NotebookStore.write(_:)`: ink → annotations → manifest → delete removed pages. Autosave is debounced (1 s) but starts within 5 s of the first unsaved change, retries failures with backoff (`SaveTiming`), and runs on the editor's serial `writeQueue` off the main actor. `saveNow()` is the synchronous flush (scene leaves `.active`, notebook closes, tests): it waits for a running write and rewrites what that write carried. Keep all of these working when touching the editor.
- Thumbnails render off the main actor (`PageThumbnailJob`); PDF pages come from a private copy of the document, never the one the `PDFView` shows. Tests that read `thumbnails` must `await editor.waitForThumbnails()` first.
- **File format** (`<uuid>.writepad/`, currently version 5):
  - `manifest.json`: title, dates (ISO 8601 with milliseconds), ordered pages. A page with `pdfPageIndex` shows that page of `source.pdf`; without it, it is paper.
  - `pages/<pageId>.drawing`: `PKDrawing.dataRepresentation()` in page coordinates.
  - `pages/<pageId>.items-<revision>.json`: text/image items in displayed page coordinates; `PageInfo.itemsRevision` selects an immutable revision.
  - `images/<assetId>.png`: immutable normalized images; item revisions/assets are written before ink and manifest, and retained for backups/undo until package purge. Missing or damaged item content stops loading without overwriting it.
  - `source.pdf`: the imported original, never modified.
  - `annotations.json`: highlights, underlines, strikethroughs and comments (`PDFMarkup`, PDF-space bounds). Markups of deleted pages are pruned.
  - `manifest.prev.json`: the previous valid manifest, read when `manifest.json` is missing or undecodable.
  - `*.corrupt`: undecodable files are renamed, never overwritten or deleted. A file that exists but can't be *read* is not damage: loading stops with an error instead of falling back.
  - Drawing files newer than the manifest but not listed in it are recovered as pages (a save crashed between ink and manifest).
  - Unknown keys in the manifest and in each page are kept (`unknownFields`, `JSONValue`) and written back unchanged.
  - A manifest with a newer `version` opens **read-only** (`EditorViewModel.isReadOnly`); `NotebookStore.ensureWritable` refuses every write to it. One this build can't decode at all throws `unsupportedVersion` and is left untouched, never quarantined.
  - Any format change must bump `NotebookManifest.currentVersion` and keep loading older versions.
- **The library index is a cache.** Packages on disk are the source of truth for titles and dates; SwiftData only adds folders. `LibraryViewModel.refresh()` re-syncs from packages.
- **UI tests must not touch real data.** Debug builds honor `WRITEPAD_STORAGE_NAMESPACE` (see `StorageLocation`); `XCUIApplication.isolated()` sets it. Launch the app before `app.open(url)` so the namespace applies.
- Keep large data (drawings, PDFs, images) as files in the package — not in SwiftData.
- Store drawings in page coordinates, not view/zoom coordinates, so export matches the screen.
- The notebook editor shows all pages on one `PKCanvasView`; `PageLayout.split` assigns each stroke to the page under its center. Page add/delete/move/paper changes bump `structureVersion`, which reloads the canvas and clears undo.
- The canvas forces light appearance (paper is white); the area around pages follows system appearance.
- UI-facing types are `@MainActor`; `@Observable` view models; `NotebookStore` stays a `Sendable` value type.
- Match existing style: small focused types, sparse comments that explain *why*, SF Symbols for icons.
- Simulator has no Apple Pencil: finger drawing defaults on in the simulator, off on device. Pressure, palm rejection and latency must be checked on a real iPad — say so when you couldn't.

## Workflow
- Work items live in `docs/TASKS.md` with a difficulty (S/M/L). Claim one by setting its Status in your first commit; leave **L** tasks to the strongest model unless a design note in that file says otherwise.
- Add or update tests in `writePadTests/` for storage and view-model logic; run the test command above before calling work done and report real results.
- One milestone item per commit where practical; commit messages in imperative mood with a short bullet body.
- Don't commit `build/`, `DerivedData/`, or `xcuserdata/` (already in `.gitignore`).
- Don't add third-party dependencies without asking the user first.
- The user may write in Indonesian or English — reply in the language they used.
